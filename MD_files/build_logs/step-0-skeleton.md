# Step 0: Project skeleton and housekeeping

**Commit:** `Set up project skeleton and seed data for RFQ scoring app`
**Goal:** a clean, installable, secret-safe starting point. No app code yet.

---

## What we did, and why

### 1. Reused the existing git repo
The folder was already a git repo (branch `main`, remote `origin` →
`github.com/KSAP02/AstroBase`, no commits yet), so we didn't run `git init` again. This is commit #1
of the history the SPEC grades ("at least 5 meaningful commits").

### 2. Rebuilt the virtual environment in place
```bash
python -m venv --clear astrobase_venv
```
A Windows venv stores **absolute paths** in its launcher scripts. `astrobase_venv` was created in an
older folder (`...\AI-applications\AstroBase\`), so `pip` still pointed there. `--clear` rebuilds the
venv at its current location under the same name. It's gitignored and never committed.

### 3. Reorganised the candidate pack

| From | To | Why |
|---|---|---|
| `candidate-pack/seed/` | `data_warehouse/seed/` | Seed data belongs in the data folder; `db.py` will read `rfqs.json` from here |
| `candidate-pack/samples/` | `data_warehouse/samples/` | Test inputs (vendor profiles) sit next to the seed data |
| `candidate-pack/BUILD_LOG.md` | `BUILD_LOG.md` (root) | SPEC: "`BUILD_LOG.md` in the repo root" |
| `candidate-pack/SPEC.md` | `MD_files/SPEC.md` | **Copied byte for byte** (checked with `cmp`), because the SPEC says "Do not edit this file" |

The empty `candidate-pack/` was then removed.

### 4. Removed scaffolding we don't need
- `mcp-server/`: an MCP server lets other AI agents call this app as tools. The SPEC doesn't ask for
  that, and CLAUDE.md says to delete unused scaffolding rather than leave it empty.
- `frontend/package.json` and `frontend/tsconfig.json` were empty files. An empty `package.json` is
  invalid JSON and would break `npm`. They're regenerated properly in Step 5; `frontend/src/.gitkeep`
  keeps the folder.
- `docker-compose.yml` is **kept** (still empty). It's filled in Steps 1 and 5.

### 5. Files written

**`.gitignore`**: what git must never commit:
- `.env` (the OpenAI key lives here; SPEC: "secrets never committed")
- `astrobase_venv/`, `.venv/`, `__pycache__/`: Python machinery, rebuilt on each machine
- `node_modules/`, `dist/`: Node machinery
- `data_warehouse/*.db`: the SQLite file is **created on first run**, so it's not source code
- `.claude/settings.local.json`: personal Claude Code settings

**`.dockerignore`**: what Docker must never copy into an image. The backend image is built from
the repo root, so without this file `docker build` would copy `.env` (the secret), the venv and the
DB into the image. It also excludes `frontend/` (which has its own image) and the docs folders.

**`requirements.txt`**: Python dependencies, unpinned (latest stable, per CLAUDE.md):

| Package | Used for |
|---|---|
| `fastapi` | The web API: routes, request validation, JSON responses |
| `uvicorn[standard]` | The server process that runs the FastAPI app |
| `pydantic` | Data models: API request/response shapes and the LLM's output schema |
| `pydantic-settings` | Loads `.env` into a typed `Settings` object (`config.py`) |
| `langchain-core` | `ChatPromptTemplate` (fills our prompt files) |
| `langchain-openai` | `ChatOpenAI`, the OpenAI chat model client, including structured output |

Installed versions at this point: fastapi 0.141, uvicorn 0.54, pydantic 2.13, pydantic-settings 2.15,
langchain-core 1.6, langchain-openai 1.6 (pulls in openai 3.19).

**`.env.example`** (committed) and **`.env`** (gitignored) have the same keys:
```
LLM_PROVIDER=openai
LLM_MODEL=
LLM_API_KEY=
LLM_BASE_URL=
DB_PATH=data_warehouse/astrobase.db
```
- `LLM_*` follow CLAUDE.md §3: choosing a provider or model is **configuration, not code**. Changing
  model = editing `.env`.
- `DB_PATH` is relative, so it resolves the same on your machine and inside Docker (`/app/...`).
- No inline `# comments`: Docker Compose's `env_file` would treat them as part of the value.
- **You fill in** `LLM_MODEL` and `LLM_API_KEY` before Step 3.

**`.claude/settings.json`** → `{}`. It was a 0-byte file, which is invalid JSON.

**`backend/__init__.py`, `backend/agents/__init__.py`**: empty files that make `backend` and
`backend.agents` importable **packages**. This is what makes `uvicorn backend.main:app` and
`python -m backend.seed` work from the repo root.

**`BUILD_LOG.md`**: filled in **Stack** and **What you skipped** (MCP removed).

**`README.md`**: a two-line placeholder; the real instructions come in Step 6.
